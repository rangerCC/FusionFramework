## 一、PoC 目标（不变）

用最少成本验证三个核心假设：

| # | 核心假设 | 成功标准 |
|---|---|---|
| 1 | 家长愿意为 AI 生成的个性化社交故事**一次性付费买断** | ≥50% 测试用户完成真实付款 |
| 2 | Coze 工作流生成的故事质量达到可接受水准 | 家长打分平均 ≥3.5（1-5分） |

## 二、老板建议的影响分析

### 建议 1：去掉账号系统，用设备唯一 ID 作关联 key

**现状**：
- `AccountKit` 整套（`SSAccountService` 协议、`SSMockAccountService`、`SSRemoteAccountService`、`AccountManager`）围绕手机号登录构建
- `SSProfilePageController` 显示登录状态、头像、会员状态
- `SubscriptionManager` 通过 `AccountManager.appAccountToken` 关联购买记录
- 服务端 `users`、`auth_identities`、`refresh_tokens`、`devices` 表全部与账号体系绑定

**PoC 改造方案**：
- iOS 侧：用 `UIDevice` + `KeychainAccess` 生成一个稳定的设备 UUID（`ss_device_id`），替代 `SSUser` 和 `AccountManager`。`SubscriptionManager` 的 `appAccountToken` 直接用设备 UUID
- 服务端侧：`users` 表中不再需要 `auth_identities`、`refresh_tokens`；用 `device_id`（VARCHAR）直接作为用户标识，一个设备就是一个用户
- `SSProfilePageController` 大幅简化：去掉登录/登出入口，只保留「我的孩子」「订阅状态」「帮助」「设置」
- `AccountKit` 整个模块在 PoC 中不再使用（但不删除代码，保留备用）

**改造工作量**：iOS 中等（需要重构 `SubscriptionManager` 的身份绑定逻辑）；服务端中等（schema 要改）

---

### 建议 2：保留管理后台（精选故事管理 + 用户数据）

**现状**：
- 服务端 `admin` 模块：用户列表/详情、订阅管理、审计日志、精选故事管理、数据看板——全部已实现
- 管理后台前端：React + Ant Design，Dashboard/Users/Subscriptions/Featured/AuditLogs 五个页面已实现
- 精选故事已有完整 CRUD（`featured_stories` 表 + API）

**PoC 保留范围**：
- 精选故事管理（增删改排序）：这是给 App 提供内置 Demo 数据的核心途径，必须保留
- 数据看板（Dashboard）：总用户数、今日新增、今日故事生成数——PoC 验证期必须有数据观测
- 用户列表（简化）：能查看设备注册数量和买断记录

**PoC 可砍范围**：
- 订阅管理页（`SubscriptionsPage`）：迁移为买断后，原来的订阅详情页面意义不大；改为「买断记录」页面
- 审计日志页（`AuditLogsPage`）：PoC 阶段只有我们团队用后台，可暂不显示
- 额度调整（`adjustQuota`）、封禁用户（`setStatus`）：PoC 期间无需

**改造工作量**：前端小（砍掉 2 个页面、改 1 个页面）；服务端小（部分接口不用改，买断记录新增几个接口）

---

### 建议 3：付费机制改为一次性买断

**现状**：
- `SubscriptionManager` 完整封装了 StoreKit 2 订阅购买、收据验证（`/v1/subscription/verify`）、Apple Webhook（`/v1/webhook/appstore/notifications`）
- 现有订阅产品是月订阅/年订阅
- 服务端 `subscriptions` 表按 `original_transaction_id` 存储，支持过期/续订状态

**买断方案**：
- 在 App Store Connect 创建一个「**非消耗型内购（Non-Consumable IAP）**」产品，如 `com.alitrip.socialstory.unlock`，定价 ¥18 或 ¥25
- 非消耗型产品：一次购买永久有效，可「恢复购买」，StoreKit 2 验证逻辑与订阅完全一致
- iOS 侧：`SubscriptionManager` 只需将「查询是否 active」的逻辑改为「检查非消耗型产品是否已购买」，改动量极小
- 服务端侧：`subscriptions` 表可复用，`expires_at` 留 null，`status` 只用 `active`/`revoked`；Apple Webhook 中买断产品不会发 `DID_RENEW`，只需处理 `REFUND` 和 `REVOKE`，逻辑更简单

**买断的附加好处**：
- 验证付费意愿比订阅更直接，用户决策更简单（买了就永远有）
- 对 PoC 阶段的家长更友好，不用担心「忘记取消订阅」
- App Store 审核更宽松（非消耗型不需要提供订阅说明）

**改造工作量**：iOS 小（逻辑复用 95%，主要改 UI 文案）；服务端极小（schema 不用动）

---

### 建议 4：UI 需要重新设计

**现状判断（设计师接手后需要出评审报告）**：
- 所有 UI 均为手写 UIKit frame 布局，无设计稿
- 整体视觉风格功能性有余、情感化不足——这是面向 ASD/ADHD 儿童家长的产品，UI 需要有温暖感、易读性和信任感
- 颜色系统：`SSTheme` 有 `accentColor`、`cardColor`、`backgroundColor`、`primaryTextColor`、`secondaryTextColor`，已做主题化抽象，改起来有基础
- 字体、间距、圆角：当前数值是程序员感觉出来的，缺乏系统性

**PoC UI 设计范围**（需设计师出稿，iOS 实施）：

| 页面 | 设计优先级 | 核心关注点 |
|---|---|---|
| 故事库（首页） | P0 | 精选故事卡片视觉、空状态引导 |
| 故事生成页 | P0 | 表单易用性、子档案卡片、CTA 按钮 |
| 故事阅读页 | P0 | 插图区比例、文字排版、音频控制栏 |
| 买断付费页 | P0 | 价值传达、一键购买、信任感 |
| 子档案管理 | P1 | 列表卡片、编辑表单 |
| 我的/设置页 | P1 | 简化后的个人主页 |
| App 图标 & 启动页 | P1 | 品牌一致性 |

**设计交付要求**：
1. 色彩规范（主色、辅色、背景色、文字色，支持 `SSTheme` 直接对应）
2. 字体规范（标题/正文/辅助文字的字号和字重）
3. 核心页面高保真设计稿（Figma），P0 页面必须覆盖
4. 组件规范（卡片、按钮、表单元素）

```
┌──────────────────────────────────────────────────────┐
│                    iOS App（TestApp）                  │
│                                                      │
│  故事库 → 生成（Coze）→ 阅读（AVPlayer/TTS）           │
│  子档案管理（本地 FMDB）                               │
│  一次性买断（StoreKit 2 Non-Consumable）               │

└──────────────┬───────────────────────────────────────┘
               │  HTTPS
               ▼
┌──────────────────────────────────────────────────────┐
│                Go 服务端（精简版）                      │
│                                                      │
│  POST /v1/device/register  ← 设备注册（首次启动）      │
│  POST /v1/purchase/verify  ← 买断收据验证              │
│  POST /v1/webhook/appstore ← Apple 通知（退款处理）    │
│  GET  /v1/stories/featured ← 精选故事列表（ETag）      │

└──────────────────────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────────────────┐
```

- `auth`（短信验证码、JWT、refresh token）
- `account`（昵称/头像/OSS 上传）
- `children` API（子档案存本地）
- `usage`（免费配额计数）

## 四、数据库 Schema 变更（服务端）

### 保留并改造

```sql
-- users 表：去掉手机号/昵称/头像，只留设备标识
CREATE TABLE users (
  id               BIGINT PRIMARY KEY,         -- snowflake
  public_id        VARCHAR(32) NOT NULL UNIQUE, -- "u_xxx"，对外暴露
  device_id        VARCHAR(128) NOT NULL UNIQUE,-- iOS Keychain 持久化 UUID
  app_account_token UUID NOT NULL UNIQUE DEFAULT gen_random_uuid(),
  status           SMALLINT NOT NULL DEFAULT 1,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- subscriptions 表：复用，expires_at = null 表示买断永久有效
-- 不需要改结构，只改使用语义
```

### 删除（PoC 不需要）

```sql
-- 删除：auth_identities、refresh_tokens、devices
-- 删除：usage_quota（买断用户不限次数）
```

### 新增（极小）

无需新增表，买断记录直接存入现有 `subscriptions` 表。

## 五、iOS 改造清单

### 5.1 设备身份（替代 AccountKit）

新增 `SSDeviceIdentity`（Swift，SocialStoryCore 中）：
```swift
// 职责：生成并持久化设备 UUID，作为全局身份 token
// 对外接口：
static var deviceID: String       // ss_device_id，KeyChain 持久化
static var appAccountToken: String // 与 deviceID 相同，透传给 StoreKit
```

`AccountKit` 模块整体停用（代码保留，不引用）。

### 5.2 SubscriptionManager（改为买断逻辑）

- 将 `purchaseSubscription` 改为 `purchaseUnlock`
- `canGenerateStory` 改为检查非消耗型产品是否已购买
- `appAccountToken` 改为读 `SSDeviceIdentity.appAccountToken`
- 收据验证接口从 `/v1/subscription/verify` 改为 `/v1/purchase/verify`

### 5.3 SSProfilePageController（大幅简化）

移除：登录按钮、头像、昵称、手机号显示、登出
保留：买断状态、子档案入口、帮助、设置
新增：设备 ID（供客服使用，可选显示后 8 位）

### 5.4 SSStoryAPIClient（Coze 调用）

- 请求头加 `X-Device-Id`（替代 `Authorization: Bearer`）
- 服务端通过 device_id 做频次限制（防滥用）

### 5.5 UI 全面翻新（配合设计师稿件）

按设计稿重写 P0 页面的布局和视觉层，业务逻辑不动。
