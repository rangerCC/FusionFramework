# iOS 端侧 AI 图片清理 App：开发任务拆解

依据：[iOS端侧AI图片清理App技术方案.md](iOS端侧AI图片清理App技术方案.md)（下称"方案"，章节号指方案中的章节）。

说明：

- 任务编号格式为 `阶段-序号`，例如 `M1-07`。依赖列写的是前置任务编号。
- 工时单位为人日，按一名熟练 iOS 开发估算，不含审核排队。
- 每个任务都有验收标准，验收通过才勾选。
- 标有 ❓ 的地方是我根据你的答复做的推断，你看一眼即可，有异议再改。

### 0.1 由上述决策带来的范围变化

**参考截图中有、v1 不做的内容**（截图来自一款现有产品，只参考版式）：

| 截图中的内容 | 处理 |
| --- | --- |
| "随机""压缩"两个 Tab | 不做，Tab 只保留 3 个 |
| 回忆盲盒 | 不做 |
| ≤ 2 秒视频 | 放入 v1.1，和"大视频"一起做（只需按时长筛选，工作量小） |
| 推广大使计划（佣金） | 不做，涉及分佣结算和服务端 |
| 免费照片风格转化小程序 | 不做 |
| 柯基吉祥物与插画 | 不使用。插画、吉祥物、图标需要自有设计，v1 先用占位图（M1-13） |

**新增到 v1 的内容**（方案原文没有，由 D6 带来）：

- "相册整理" Tab：按月份 / 相簿 / 类型浏览全部照片和视频，多选后删除（M1-24 ~ M1-27）；
- "我的" Tab：会员入口、问题反馈、给我们好评、重新计算相似照片、设置、使用条款与隐私政策（M1-28 ~ M1-31）；
- 快速清理页顶部的"清理小结"：照片数、视频数、数据大小、已删除数量与预计释放空间（M1-19）。

### 0.2 只有一台测试设备带来的限制

设备 Identifier 前缀 `00008140` 对应 A18 系列芯片，属于方案 11.1 的"高档"设备。只用这一台测试，有以下缺口，记为已知风险：

| 缺口 | 处理方式 |
| --- | --- |
| 中、低档设备的性能无法实测 | 代码照常实现分档逻辑（M2-08、M2-09），但性能只验收高档指标 |
| iOS 15 / 16 的代码路径（FeaturePrint Revision1、无持久化变更追踪）无法真机验证 | 用 iOS 15、16 模拟器做功能验证，不做性能验证 |
| 无法测试跨设备 iCloud 同步删除 | 用同一 Apple ID 的 iCloud.com 网页端观察删除结果 |

如果上线前能借到一台 A12–A13 设备（如 iPhone XS / 11）和一台 iOS 15/16 设备，建议补测一轮。

## M0 工程搭建与技术验证

目标：验证识别管线在真机上的精度与性能，不做正式 UI。M0 结束时评审，决定阈值初值和是否需要调整方案。

### 工程基础

- [x] **M0-01 新建 App target 与 Pod 模块**（2 天）
  - 新建 App target `PhotoCleaner`，Bundle ID `com.kevinapp.CleanPhoto`，最低系统 iOS 15.0，加入 `Workspace/FusionWorkspace.xcworkspace`，Podfile 增加对应 target。
  - 新建本地 Pod `PhotoClean.podspec`，依赖 FusionBase、FusionCore、Utility、FMDB；源码目录 `PhotoClean/PhotoClean/`，Lua 目录 `PhotoClean/Script/Service/`、`PhotoClean/Script/Page/`。
  - 配置 `HEADER_SEARCH_PATHS` 引入 `SafeARC.h`；链接 Photos、Vision、Accelerate、BackgroundTasks、StoreKit。
  - 需要你提供：开发者账号的 Team ID（真机签名用）。
  - 验收：`pod install` 后 `xcodebuild` 编译通过，模拟器启动出空白页。

- [x] **M0-02 真机环境确认**（0.5 天，依赖：M0-01）
  - 确认「Kevin 自用」的 iOS 版本、开发者模式已开启、签名证书与描述文件可用。
  - 验收：空白 App 在该设备上安装并启动成功。

- [x] **M0-03 实现 `IFusionConfig` 配置提供者**（1 天，依赖：M0-01）
  - 现状：`TestApp` 只初始化了 `FusionPageNavigator`，没有调用 `[[FusionCore getInstance] prepareWithConfig:]`，消息系统并未启用。
  - 新建 `PCFusionConfig`，实现 `appScheme`、`getCoreService`、`getLogicServiceByName:`，从 `config.zip` 读取 Lua 生成的配置。
  - 在 `AppDelegate` 中初始化 FusionCore 与页面导航器。
  - 验收：发送一条到测试 Actor 的消息，在发起线程收到 `FusionNativeMessageNotification`，状态为 Finish。

- [x] **M0-04 Lua 注册与宏生成**（0.5 天，依赖：M0-03）
  - 确认 `Workspace/MacroMaker.lua` 能扫描到 `PhotoClean/Script/` 下的文件，必要时调整扫描路径。
  - 注册 `scanService`、`photoLibService` 骨架（方案 3.2、17.6）。
  - 验收：`lua MacroMaker.lua` 生成 `SCANSERVICE_SERVICE`、`HASHACTOR_ACTOR` 等宏，代码中可引用。

- [ ] **M0-05 日志与性能打点**（1 天，依赖：M0-01）
  - 基于 CocoaLumberjack 封装日志宏，Release 包不输出照片相关信息。
  - 封装 `os_signpost` 宏，覆盖元数据同步、Stage 1、Stage 2、聚类、删除五个阶段（方案 11.2）。
  - 验收：Instruments 中能看到五个阶段的区间。

- [ ] **M0-06 上架信息占位文件**（0.5 天，依赖：M0-01）
  - 新建 `PhotoCleaner/Resources/PublishInfo.plist`，所有字段先填占位值：上架主体名称、ICP 备案号、客服邮箱、隐私政策 URL、使用条款 URL、App Store ID。
  - 新建 `docs/上架信息.md`，说明每个字段的用途、显示位置、填写要求。
  - 代码只通过 `PCPublishInfo` 读取这些字段，不在别处硬编码。
  - 验收：改 plist 中的值后重新编译，"我的"页、设置页、反馈邮件中的内容随之变化（M1 完成后验收）。

### 识别管线原型

- [x] **M0-07 dHash 与低信息量过滤**（1 天，依赖：M0-01）
  - 实现方案 17.1 的 `PCDHash`、`PCHamming`、`PCHashIsInformative`。
  - 单元测试：同图不同尺寸距离 ≤ 2；纯色图被过滤；旋转 90° 距离明显增大。
  - 验收：单元测试通过；测试机上单张耗时 ≤ 0.5ms。

- [x] **M0-08 多索引哈希**（1 天，依赖：M0-07）
  - 64 位切 5 段（13/13/13/13/12），查询返回 Hamming ≤ 4 的候选（方案 4.4、17.2）。
  - 单元测试：1 万条随机哈希 + 注入的近重复样本，与暴力两两比较结果完全一致。
  - 验收：1 万条全量查重 ≤ 1 秒。

- [ ] **M0-09 标注集与标注工具**（3 天，依赖：M0-01）
  - Debug 页面：在本机按时间浏览照片，标注"重复 / 相似 / 不相似"照片对，导出 JSON（只含 `localIdentifier` 与标签，不含图片）。
  - 样本：≥ 20 份真实相册（本人同意，标注只在其本人设备上完成）+ 自行拍摄的构造样本（连拍、文档翻拍、同图多次保存、纯色/黑屏截图等边界情况）。
  - 验收：≥ 3000 个标注对，方案 4.8 列出的场景均有样本。

- [x] **M0-10 FeaturePrint 提取与版本固定**（1.5 天，依赖：M0-01）
  - 实现方案 17.3：显式设置 revision（iOS 17+ 用 Revision2，否则 Revision1）。
  - float16 向量存取（`vImageConvert_PlanarFtoPlanar16F`）与 vDSP L2 距离。
  - 验收：自算距离与 `computeDistance:` 的判定一致率 ≥ 99.5%；Revision2 在测试机上验证，Revision1 在 iOS 16 模拟器上做功能验证。
  - 进展：iPhone 16（iOS 27.0）上 Revision2 为 768 维，单张 5.15ms，判定一致率 100%（780 对合成图）。本机没有 iOS 15/16 模拟器运行时，Revision1 尚未验证，需先在 Xcode 中下载 iOS 16 模拟器。

- [x] **M0-11 时间窗候选与聚类原型**（2 天，依赖：M0-08、M0-10）
  - 时间窗：每张照片与之后 60 秒内最多 10 张组成候选对；同一 `burstIdentifier` 全部成为候选（方案 4.4）。
  - 聚类：以组代表为中心的贪心聚类，组上限 50 张；重复组用并查集，与相似组不重叠（方案 4.6）。
  - 验收：单元测试通过，包括 A~B~C 链式样本中 A、C 不因 B 合并。

- [ ] **M0-12 离线评估工具与阈值标定**（2 天，依赖：M0-09、M0-11）
  - Debug 页面跑完整管线，对照标注集输出精确率、召回率、误分组样例（只在本机显示）。
  - 标定 Revision2 的距离阈值（Revision1 阈值用模拟器上的同一批样本标定，上线前标记为"未经真机验证"）。
  - 验收：输出标定报告；精确率 ≥ 90%（M0 退出标准，正式上线标准为 95%）。

- [ ] **M0-13 真机性能摸底**（1 天，依赖：M0-12）
  - 在测试机上用 ≥ 1 万张的相册测 Stage 1 全量耗时、Stage 2 单张耗时、内存峰值、20 轮连续扫描的吞吐保持。
  - 验收：输出性能报告，对照方案 11.2 的"高档"列。

- [ ] **M0-14 M0 评审**（0.5 天，依赖：M0-12、M0-13）
  - 交付：标定报告、性能报告、阈值初值、对方案的修订建议。
  - 验收：你确认是否进入 M1。

## M1 核心链路与三个 Tab

目标：三个 Tab 全部可用；从授权、扫描到删除的闭环跑通。

### 数据层

- [ ] **M1-01 数据库与迁移框架**（2 天，依赖：M0-14）
  - 按方案 5.2 建表；`asset` 表增加 `media_type`（照片 / 视频）与 `duration` 字段，供相册整理与清理小结使用。
  - `FMDatabaseQueue` 单例；schema 版本号与逐版本迁移；外键级联。
  - 文件位于 `Library/Application Support/`，排除备份，文件保护级别 `CompleteUntilFirstUserAuthentication`（方案 5.1）。
  - 验收：单元测试覆盖建表、迁移、级联删除；数据库损坏时自动删除并重建。

- [ ] **M1-02 数据访问层（DAO）**（2 天，依赖：M1-01）
  - 资产批量 upsert、按时间/月份查询、按 `scan_state` 取待扫描批次、分组读写、删除日志写入与 90 天清理、清理小结统计。
  - 验收：1 万条资产批量写入 ≤ 1 秒；单元测试通过。

### PhotoKit 层（`photoLibService`）

- [ ] **M1-03 `authActor`：授权查询与请求**（1 天，依赖：M0-04）
  - `requestAuthorizationForAccessLevel:PHAccessLevelReadWrite`；返回五种授权状态。
  - Info.plist：`NSPhotoLibraryUsageDescription` 按方案 9.1 措辞；`PHPhotoLibraryPreventAutomaticLimitedAccessAlert = YES`。
  - 验收：五种状态在测试机上均能正确返回（通过系统设置切换授权）。

- [ ] **M1-04 `syncActor`：全量元数据同步**（2 天，依赖：M1-02、M1-03）
  - 拉取全部照片与视频（`includeAllBurstAssets = YES`），读取元数据写入 `asset` 表，不解码图片。视频只同步元数据，不参与相似识别。
  - 截图分类、连拍分组在此阶段直接生成。
  - 验收：1 万张 ≤ 1 秒；截图数量与系统"截屏"相簿一致；照片数、视频数与系统相册一致。

- [ ] **M1-05 扫描用缩略图请求封装**（1 天，依赖：M0-01）
  - 按方案 4.3：同步请求、HighQualityFormat、Fast resize、禁止网络；Stage 1 用 64px，Stage 2 用约 360px。
  - 识别仅在 iCloud 的资产；每张处理包在 `@autoreleasepool` 中。
  - 验收：扫描过程中不触发任何 iCloud 下载；仅云端的照片被标记为 `scan_state = 3`。

- [ ] **M1-06 `PCScanService` 并发控制**（1.5 天，依赖：M0-04）
  - 子类化 `FusionService`，重写 `canConcurrentExecute:`，`featureActor` 在途上限按设备档位取 1 或 2（方案 17.5）。
  - 暂停/恢复开关，供 M2 热管理使用。
  - 验收：压测时 `featureActor` 同时在途数从未超过上限（日志验证）。

### 扫描层（`scanService`）

- [ ] **M1-07 `scanActor`：扫描调度**（2 天，依赖：M1-04、M1-06）
  - 父消息"扫描"，按"最新优先"每 200 张派生一个 `hashActor` 子消息；Stage 1 完成后派生 `featureActor`、`clusterActor` 子消息。
  - 每批完成写库作为断点；取消扫描调用 `asyncCancelMessage:`。
  - 进度通知 `PCScanProgressNotification`（已处理数、总数、阶段），在主线程发出。
  - 验收：扫描中杀掉 App，重启后从断点继续；取消后所有子消息停止。

- [ ] **M1-08 `hashActor`**（1 天，依赖：M0-07、M1-05、M1-07）
  - 验收：测试机上 1 万张 Stage 1 ≤ 20 秒。

- [ ] **M1-09 `featureActor`**（1 天，依赖：M0-10、M1-05、M1-07）
  - 只处理候选照片；记录 revision；跨 revision 的候选对按需重算旧特征。
  - 验收：非候选照片不提取特征（日志计数验证）。

- [ ] **M1-10 `clusterActor`**（2 天，依赖：M0-11、M1-08、M1-09）
  - 生成重复组与相似组；成员 < 2 的组删除。
  - 验收：在标注集上精确率 ≥ 95%（达不到则回到 M0-12 调阈值）。

- [ ] **M1-11 推荐保留（第一版）**（1.5 天，依赖：M1-10）
  - 规则：收藏 > 连拍系统选择 > 分辨率 > 非截图 > 时间（方案 4.7），质量分在 M2 补充。每张推荐保留的照片记录理由。
  - 验收：单元测试覆盖每条规则的优先级；收藏照片的 `keep_rank` 始终为 1。

- [ ] **M1-12 `sizeActor`：空间估算**（1 天，依赖：M1-04）
  - 照片按像素数与格式估算，视频按时长 × 分辨率对应的码率估算（方案 8.4）；`fileSize` KVC 只保留开关，默认关闭且 v1 不打开。
  - 验收：在 200 个样本上估算误差中位数 ≤ 30%（开发环境下打开 KVC 开关取真实值对照，对照完即关闭）。

### 公共 UI

- [ ] **M1-13 视觉规范与主题**（2 天）
  - 新建 `PCTheme`：颜色、字体、圆角、阴影、间距常量，所有页面只引用 `PCTheme`。
  - 色板初稿：以淡蓝色为基础色（页面背景淡蓝、卡片白色、主按钮与强调色为较深的蓝），具体色值出一页色板给你确认。参考截图中的橙色强调色全部替换为蓝色系。
  - 公共组件：圆角卡片、主按钮（如"删除 N 项"浮动按钮）、分段控件（月份 / 相簿 / 类型）、空状态视图、Toast。
  - 插画与 Tab 图标：v1 先用 SF Symbols 和占位图，自有插画到位后替换。
  - 验收：你确认色板与组件截图。

- [ ] **M1-14 TabBar 与页面骨架**（1.5 天，依赖：M0-04、M1-13）
  - 基于 `FusionTabBar` 实现 3 个 Tab：快速清理、相册整理、我的。
  - 所有页面类建空壳，Lua 注册，`PCAdapter` 实现 `IFusionPageAdapterProtocol`。
  - 页面间只传 `localIdentifier` 数组与分组 ID，不传 `PHAsset` 对象。
  - 验收：3 个 Tab 可切换，所有页面可以互相跳转。

- [ ] **M1-15 授权引导与各授权状态页面**（2 天，依赖：M1-03、M1-14）
  - 首屏不弹权限，点"开始扫描"才请求。
  - Denied/Restricted：说明页与"去设置"按钮；Limited：快速清理页顶部常驻提示，可调起 `presentLimitedLibraryPickerFromViewController:`（方案 9.1）。
  - 三个 Tab 在未授权时都显示同一个引导视图，不白屏。
  - 验收：五种授权状态下三个 Tab 均无白屏；受限访问下新增授权照片后能触发增量扫描。

- [ ] **M1-16 网格缩略图组件**（2.5 天，依赖：M1-14）
  - `PHCachingImageManager`，`targetSize` 以像素计，预热窗口上下各一屏，按差集启停缓存；cell 复用时取消旧请求并校验 `localIdentifier`（方案 7.2）。
  - 支持多选模式与视频时长角标。快速清理的组详情、相册整理的详情页共用这一个组件。
  - 验收：1 万张网格快速滚动无错图、无闪烁；内存峰值 ≤ 80MB。

- [ ] **M1-17 `deleteActor` 与删除确认页**（2.5 天，依赖：M1-02、M1-16）
